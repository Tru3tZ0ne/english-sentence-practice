我要你直接为我开发一个可长期维护的 Windows 本地英语学习应用。

不要只给我示例代码、框架或伪代码。
请直接在当前工作目录创建完整可运行项目，完成之后实际运行、自测、修复报错，直到可以正常启动。

我会长期继续让 Codex 修改这个项目，所以：

1. 架构必须简单、清晰、模块化。
2. 不要为了“先进”引入不必要的复杂技术。
3. 内容题库与程序逻辑必须彻底分离。
4. 以后增加新题库时，原则上不需要修改程序代码。
5. 必须为未来的 Codex 留好开发文档和约定。
6. Windows 下必须非常容易启动。
7. 不使用 Docker。
8. 不需要云服务器。
9. 不需要 Node.js / npm / pnpm。
10. 尽量减少依赖。


==================================================
一、产品目标
==================================================

这是一个本地运行的英语句子练习 APP。

视觉和交互可以参考我提供的截图：

- 顶部是“听写练习”
- 有整体学习进度条
- 显示当前题库
- 显示当前第几题 / 总题数
- 中间区域非常干净
- 中文句子作为提示
- 用户输入对应英文
- 可以提交答案
- 对答案进行正确/错误反馈
- 可以上一题、下一题
- 可以收藏
- 支持键盘快捷键
- 整体界面适合长时间学习

不要完全照抄截图，而是做一个简洁、现代、耐看的版本。

重点是“学习效率”和“后期维护”，不是炫技。

==================================================
三、Windows 启动要求
==================================================

这是非常重要的要求。

项目根目录必须提供：

start.bat

用户以后正常使用时，只需要双击：

start.bat

就可以打开 APP。

start.bat 要做到：

1. 找到项目目录，不依赖用户当前 shell 所在路径。
2. 检查 .venv 是否存在。
3. 第一次运行时自动创建 Python venv。
4. 自动安装 requirements.txt。
5. 后续启动时不要每次重复安装。
6. 启动应用。
7. 启动失败时不要直接闪退。
8. 在终端中给出清晰的中文错误信息。
9. 路径中存在中文、空格时也要正常工作。

优先检测 Windows 的：

py -3

如果没有再尝试：

python

如果完全没有 Python，要明确提示用户安装 Python 3，而不是莫名其妙关闭窗口。

另外提供：

reset_env.bat

用于删除并重新创建开发环境。

再提供：

build_release.bat

使用 PyInstaller 将程序打包成 Windows 可独立运行版本。

目标是未来可以生成一个 release 目录，让没有 Python 环境的 Windows 电脑也能直接运行。

不要要求用户手工输入一堆命令。


==================================================
四、应用生命周期
==================================================

UI 虽然使用网页技术，但是不要默认在普通 Chrome 标签页中运行。

优先使用 pywebview 创建本地窗口。

原因：

我希望“网页窗口”和程序生命周期绑定。

要求：

1. 用户关闭 APP 窗口时：
   Python 主程序、数据库连接、后台任务全部正常结束。

2. 页面右上角提供：
   “关闭应用”按钮。

3. 点击“关闭应用”后：
   - 保存当前学习状态
   - 关闭数据库
   - 关闭 pywebview
   - Python 程序退出

4. 不允许点关闭以后 Python 还残留在后台。

5. Windows 任务管理器里不能留下无意义的后台 Python 进程。

如果需要，可以封装统一的 Application.shutdown()。

==================================================
七、答案判断
==================================================

不要单纯做完全字符串相等。

建立独立模块，例如：

app/services/answer_checker.py

至少支持：

- 忽略英文大小写
- 忽略首尾空格
- 连续空格归一化
- 常见英文标点归一化
- ASCII 单引号和英文弯引号兼容
- 可配置是否忽略句末标点

题库可以提供多个正确答案，例如：

"answers": [
  "I'm completely over you.",
  "I am completely over you."
]

其中第一个为标准展示答案。

其它是允许答案。

不要做过度模糊匹配导致错误答案也判正确。

代码结构上要方便未来继续增加：

- contractions
- spelling tolerance
- alternative expressions

但是第一版不要过度设计。


==================================================
八、题库架构：这是整个项目最重要的部分
==================================================

题库绝对不要硬编码到 Python、HTML 或 SQLite 里面。

建立：

content/
  libraries/

每一个题库都是一个独立 JSON 文件。

例如：

content/libraries/daily_english_2000.json
content/libraries/travel_english.json
content/libraries/business_english.json


APP 启动时自动扫描：

content/libraries/*.json

自动加载所有合法题库。

增加新 JSON 文件后，重新启动 APP 就应该自动出现。

不允许每增加一个题库还要去 Python 代码里注册。


建议的数据结构：

{
  "schema_version": 1,
  "id": "daily_english_2000",
  "title": "日常口语 2000 句",
  "description": "高频日常英语表达",
  "language": "en-US",
  "tags": ["日常", "口语"],
  "items": [
    {
      "id": "daily_0001",
      "zh": "回头见。",
      "en": "See you later.",
      "answers": [
        "See you later."
      ],
      "notes": "",
      "tags": [],
      "difficulty": 1
    },
    {
      "id": "daily_0002",
      "zh": "我对你彻底没感觉了。",
      "en": "I'm completely over you.",
      "answers": [
        "I'm completely over you.",
        "I am completely over you."
      ],
      "notes": "be over someone 可以表示已经不再喜欢某人",
      "tags": [],
      "difficulty": 2
    }
  ]
}


要求：

library id 永久稳定。

item id 永久稳定。

不要用数组 index 当作进度 ID。

这样以后题库增加、调整顺序，也不会导致用户学习记录错乱。


==================================================
九、题库校验
==================================================

创建独立题库 loader 和 validator。

例如：

app/content/library_loader.py
app/content/schema.py

启动时校验：

- JSON 是否合法
- library id 是否重复
- item id 是否重复
- zh 是否存在
- en 是否存在
- answers 是否有效

单个题库坏掉时：

不要导致整个 APP 崩溃。

应该：

跳过这个题库
+
记录错误
+
在题库管理界面显示：

“business_english.json 加载失败：第 XXX 项缺少 en”


最好提供一个命令：

python tools/validate_libraries.py

用来一次验证所有题库。
