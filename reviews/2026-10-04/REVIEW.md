## 内容问题的证据

1. `generate_topic_libraries.py` 只更换主题标签，不更换句子素材。因此教育、环境、科技、职场、健康、文化 6 个库的英文集合完全相同。
2. `generate_more_topics.py` 同样导致学术、银行、投诉、家庭、租房、医疗、公共服务、人际 8 个库的英文集合完全相同。所谓医疗题没有症状、检查或预约语境。
3. `generate_ielts_3000.py` 的循环在第一个开头尚未用完时已经达到 3000 条上限，全部使用 `This trend suggests that`。`split_ielts_topics.py` 按数组切块分库，没有按语义分类。
4. `generate_comprehensive_5000.py` 的场景标签没有参与英文生成，换场景后又生成相同组合，产生 1,160 条库内重复；前两个场景就达到上限，原描述宣称的完整场景覆盖并不存在。
5. `generate_1000.py` 把 `I` 与 `are looking`、`We` 与 `is worth discussing` 直接拼接。末尾补数还用 `en[:-1]` 切掉真实词尾，例如将 `down` 截为 `dow`，再附加练习编号。
6. 多数原题 `answers` 仅复制标准句，讲解整库相同；难度取模分配或固定标为 4，不能反映实际学习负担。

| 示例 | 修改前 | 修改后 |
| --- | --- | --- |
| 雅思教育 `ielts_0001` | `... prioritise investment in inequality in educational opportunities ...`，语义成了投资于不平等 | `Although tuition fees are waived, transport costs may still prevent rural students from attending university.` |
| 日常 `daily_0035` | `I are looking for an answer today.` | `This coat is warmer than it looks.`，切换为有独立价值的比较表达 |
| 医疗 `medical_english_001` | 泛泛的“了解方案、找到合理解决办法” | `I've had a sore throat for three days, especially when I swallow.`，学习症状与持续时间 |

完整数字见 [内容审计](content-audit.json)，每个库的 ID 去留见 [变更清单](content-changes.json)。旧题仍完整保存在 ZIP 中，不在正式库里继续展示。

## 程序审查：仍待修复

优先级：P1 为可能影响答案、统计、启动或内容安全呈现的问题；P2 为体验、健壮性和长期维护问题。以下位置基于当前源码，不宣称已在原生窗口完成全部复测。

| 优先级 | 位置与问题 | 证据、影响与建议 |
| --- | --- | --- |
| P1 | `web/js/pages/practice-page.js`：提交缺少互斥和已提交保护 | 同题连续调用 `submit()` 发出两次记分请求；增加提交中锁、明确重试语义，并让响应绑定题目与会话 |
| P1 | 同文件：自动下一题定时器没有生命周期管理 | 已提交后切到另一题库，旧定时器仍将新库从第 1 题推到第 2 题；离开题目时取消定时器，并核验会话标识 |
| P1 | 同文件：收藏触发全量 `render()` | 填入 `draft answer` 后收藏，输入变为空；只更新收藏按钮或先保存输入草稿，不重置作答状态 |
| P1 | 练习页、题库页、`app.js`：内容直接插入 `innerHTML` | 无害探针 `<b>literal markup</b>` 被原样插入 HTML。导入的题库文本可被当作标记执行；正文使用 `textContent`，需要样式时显式创建元素 |
| P1 | `app/services/progress_service.py:9`、`app/database.py`：一次作答分多次提交 | 临时数据库中人为使第二次写入失败，结果 attempts=1、progress=0；同一次作答、统计和位置应在同一事务内提交 |
| P1 | `app/config.py:7` 与 `build_release.bat`：打包资源根目录不匹配 | 当前环境 PyInstaller 6.22.3 默认资源在 `_internal`，应用却按 exe 同级查找 `web/`、`content/`；分离资源路径和可写数据路径，并做真实发布包冒烟验证。本轮未构建完整发布包 |
| P2 | 练习页 `move()` 与全局快捷键 | 空序列调用 `move(1)` 抛出读取 `undefined.id` 的异常；快捷键仅在练习页生效，空序列提前返回 |
| P2 | 设置页、练习页与 `app.js` | `auto_speak` 被保存却未在渲染时使用；“跟随系统”只落为浅色，没有监听系统配色；补齐功能和相应验证 |
| P2 | `app/content/library_loader.py:26` | 非 UTF-8 文件触发 `UnicodeDecodeError` 并穿透逐文件隔离；应把编码错误也作为单库失败，前端展示 `library_errors` |
| P2 | `app/content/schema.py:50,83`、设置服务 | Python 的 bool 被当作 int，`schema_version: true` 与 `difficulty: true` 能通过；设置值也缺少类型、非法数字等边界验证。使用严格类型检查，保持 schema v1 合法输入兼容 |
| P2 | `app/services/library_service.py:23` | 每道题线性查找 item，并各查一次收藏，构成 O(n²) 查找和 N 次 SQL；建立内存 ID 索引，一次读取收藏集合。当前精简暂时缓解，后续扩库前应修复 |
| P2 | 答案比对与练习模式 | 当前只支持规范化后的列举答案，不能识别所有合理翻译。先扩充经审校的 `answers`，再明确区分听写与翻译练习；不直接引入云端判分或无约束模糊匹配 |
| P2 | 错题、学习统计和界面状态 | 后端已有 `wrong` 序列但无入口；错题只看历史 wrong_count，之后答对仍长期保留；主页统计只在启动 bootstrap 时获取。明确掌握标准并刷新统计 |
| P2 | 显示答案与提示状态 | 查看答案复用“错误”结果样式；隐藏提示未同步清除答案结果区；短句可能几乎全被提示。分开“查看”“提交”“提示级别”的状态与反馈 |
| P2 | 测试与源码可读性 | 现有仅 5 个核心测试，未覆盖前端状态、桥接、设置、发布包和内容语义；前端及部分 Python 压为长行。先增加关键回归，再按模块格式化，保持现有技术栈 |
| P2 | 开发与发布流程 | 无 Git 仓库；依赖范围较宽，安装标记不反映 requirements 内容变化，打包失败也会打印“已生成”。后续建立版本控制、可复现依赖和明确的发布检查 |

前端复现使用 Node VM 与最小 DOM/API 替身，未新增应用依赖；它验证状态和调用行为，不代替原生窗口视觉测试。后端复现使用临时目录和临时数据库。结果见 [前端探针](frontend-probes.json) 与 [后端探针](backend-probes.json)。HTML 探针仅检查未转义标记，不执行攻击脚本。打包、性能、主题及若干状态问题为静态审查结论，未声称经过完整端到端验证。
